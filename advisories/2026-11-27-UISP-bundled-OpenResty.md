# UISP — Bundled OpenResty/nginx and the November 2026 nginx CVEs (NOT CONFIRMED BY UBIQUITI)

> **NOT CONFIRMED BY UBIQUITI.** UISP's web interface is reported by community sources to use OpenResty (an nginx distribution); this has not been confirmed by Ubiquiti. Whether a given UISP release uses an affected OpenResty/nginx version, and whether its configuration exposes each flaw, has not been confirmed by Ubiquiti either. This advisory has been reported to Ubiquiti and will be updated with their answer.

| Field | Details |
|---|---|
| **ID** | MITS-2026-0010 |
| **Product** | UISP (Ubiquiti), through the OpenResty/nginx that community sources report it uses. |
| **Summary** | The November 2026 nginx update (nginx 1.31.9 and 1.30.7) fixes ten CVEs, and a later update (1.31.10 and 1.30.8) fixes one more. OpenResty is built on nginx, so an OpenResty release based on an affected nginx version is also in range. UISP may be affected if it uses OpenResty based on an affected nginx version; **not confirmed by Ubiquiti**. |

| **Ubiquiti status** | No UISP update or advisory from Ubiquiti about these CVEs is cited here. Check Ubiquiti's UISP release notes for updates. |
| **Recommended action** | Apply Ubiquiti's UISP update as soon as one that addresses these CVEs is released. |
| **Note (Master IT Support)** | General hardening, not a vendor recommendation: (1) limit access to the UISP web interface to trusted management networks; (2) disable HTTP/2 where it is not needed (see [CVE-2026-123007](2026-11-26-CVE-2026-123007.md) for the nginx directives). UISP manages its own nginx configuration: a manual change may be overwritten by a UISP update and is not supported by Ubiquiti, so check with Ubiquiti before changing it. |
